# One published package, pm2 installed rather than shipped, apps addressed by name

The server keeps shipping inside the single `@lamsal-de/gueterbahnhof` package: `bundle.js` esbuilds the CLI (including the fleet lifecycle imported from `server-tanstack`'s source) and copies the built server output alongside it. **pm2 is a declared dependency** (`"pm2": "^6.0.14"`) rather than something we ship, and the traced `server-output/server/node_modules` is deleted from the tarball. Managed apps are addressed by their plain app name, with `namespace: "gueterbahnhof"` set as a **label only**.

## Consequences

- **Version 1.0.0 was unusable and this is why.** Nitro traces externalised dependencies into `.output/server/node_modules` as a `.nf3` content store plus symlinks. `npm pack` includes the files but silently drops the symlinks, so pm2 shipped without its `async` dependency and every install died with `Cannot find module 'async/eachLimit'`. Tracing cannot be disabled — nitro hardcodes it for production builds — but the copy is safe to discard, because `pm2` is the only bare import in the entire output and nothing reads that directory at runtime.
- **The "zero runtime dependencies" goal is abandoned deliberately.** It was self-imposed, and it is what produced the break. One installed pm2 also satisfies ADR-0003's requirement that the client which spawns the daemon and the client the server drives be the same version — pm2 refuses a mismatched client.
- **Splitting the server into its own package would not have helped**: it would publish the same traced tree and lose the same symlinks. It would also cost the single-bin promise (`pnpx @lamsal-de/gueterbahnhof deploy` in the GitHub Action) and double the release mechanics.
- **A namespace does not isolate anything.** pm2 resolves `stop`/`delete`/`restart`/`describe` by name across every namespace (`Client.js:678-700` matches on `pm2_env.name` alone; `API.js` tries names before namespaces), so the label only groups the fleet in `pm2 list` and enables `pm2 stop gueterbahnhof` as a manual lever. **Accepted risk:** on the shared `~/.pm2`, a foreign process sharing an app name would be affected by our operations. This was chosen knowingly — `pm2 logs <app>` and `pm2 restart <app>` working out of the box is worth more on a single-operator host than protection against a collision that would itself be a misconfiguration. Reading the process list is filtered by the label, since reading is safe; only addressing is not.
