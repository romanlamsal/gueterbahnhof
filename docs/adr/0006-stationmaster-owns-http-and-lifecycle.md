# The Stationmaster owns HTTP assembly and the fleet lifecycle

The **CLI package parses argv and nothing else.** Everything between "the arguments are known" and "the process is serving" — applying the environment the built server reads, booting the fleet, installing signal handlers, assembling the HTTP server, and listening — moves into a single entry exported from `server-tanstack`: the **Stationmaster**. The CLI's `server` command defines flags, validates them, resolves where its own bundled server output sits on disk, and makes one call.

That last parameter is the only concession: only the CLI knows its published layout, so the server-output path is passed in rather than discovered. Everything else the Stationmaster does for itself.

This amends ADR-0003 rather than superseding it. Its substance is untouched — the nitro app still does no boot work, boot still completes before anything listens, and an ungraceful death still leaves apps running. Only the attribution changes: the *Stationmaster* owns the lifecycle, not the CLI.

## Consequences

- **"Outside the nitro bundle" is not the same as "in the CLI", and conflating them was the original mistake.** `runtime/lifecycle.ts` and `runtime/create-services.ts` are already `server-tanstack` source that esbuild pulls into the CLI binary rather than nitro pulling into its output (ADR-0004 describes exactly this). Express was in the CLI because it must `import()` the built server output — a real constraint, since source cannot import its own build product — but that constraint only rules out the *nitro bundle*, not the server *package*. The Stationmaster joins the category that already existed.
- **Anything that must sit in front of the nitro app now has somewhere to live.** Before this, a server concern above the nitro app had to be written in the CLI, where it does not belong, or contorted into the nitro app, where it does not fit. That is not hypothetical: the reverse proxy was designed twice, once around each bad option, before the seam itself was questioned.
- **A rejected workaround, recorded so it is not rediscovered as a good idea.** A nitro plugin *can* intercept every request ahead of the router by wrapping `nitroApp.fetch` — verified against a production build, matching on both `X-Forwarded-Host` and `Host`, with unmatched requests falling through untouched. It works. It was rejected because it intercepts *behind* the static handler, so gueterbahnhof's own `favicon.ico` and `robots.txt` would answer a proxied app's requests, and because nitro's websocket support is a server abstraction rather than a tunnel, making websocket proxying a hand-written frame-shuttling exercise. The plugin's h3 instance exposes no public middleware registration either — route-verb methods exist, but the middleware array is private — so the fetch wrap was the only documented interception point available.
- **The server package gains a third kind of source, and only a directory name marks it.** There is now code compiled into the nitro output, code compiled into both it and the CLI binary, and code that must *never* reach the nitro build because it imports an HTTP framework and the built output. A route that imports the third kind produces a confusing build failure rather than a clear error. The mitigation is the Stationmaster's own directory and a comment; the escalation, if it ever bites, is a lint rule forbidding those imports from anywhere the nitro entry can reach. Note that `runtime/` is *not* that marker — `runtime/services.ts` is imported by controllers, so it holds both kinds.
- **The startup path becomes testable for the first time.** `server-command.ts` had no test — boot-before-listen, boot-failure-prevents-listen, and the double-signal guard were all unasserted. The Stationmaster takes its fleet-lifecycle and middleware-loading collaborators as *defaulted parameters* (the idiom `applyJournaldPriorityPrefixes({ env, target })` already uses), so those properties can be asserted without a process manager or a production build.
- **TLS termination becomes structurally possible.** Terminating TLS means owning the HTTP server, which a middleware-preset nitro build cannot do. It is not attempted here, but it is no longer blocked by the shape of the code.
- **The name is deliberate, and two obvious alternatives were rejected.** "Host Entry" collides with **Entry**, which already means an app's start script, and with *host* in its hostname sense. "Gueterbahnhof Host" collides head-on with `GUETERBAHNHOF_HOST`, the variable by which an app declares its public hostname — same words, different referent. In a document set where *host* already does three jobs (the machine, the public hostname, the component), the component had to give the word up.
