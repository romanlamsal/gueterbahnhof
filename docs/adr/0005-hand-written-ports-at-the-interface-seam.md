# Interfaces are hand-written only at the interface-service seam

The four interface services — `ProcessManager`, `ProcessEvents`, `AppConfigRepository`, `ArtifactStore` — declare **hand-written** types, and their adapters are annotated with them (`export const createPm2ProcessManager = (…): ProcessManager`). App services and controllers keep inferred interfaces (`ReturnType<typeof createAppService>`), and their callers depend on `Pick<AppService, "listApps">` — the subset they actually use — rather than the whole object.

## Consequences

- **The seam that gets substituted is the only one worth writing by hand.** Interface services are the layer with two implementations: the real one and whatever the tests put in its place. An inferred interface there publishes the implementation's shape to every caller — `pm2`'s `ProcessDescription` reached the app-service and deployment-service tests, which needed casts to build a fake. Hand-writing `ManagedProcess { name, status }` deleted every cast in the suite.
- **Services and controllers are not that seam.** Nothing substitutes a second `AppService`; the layer above mocks it, and `Pick<>` already narrows the contract to what that caller uses. Hand-writing those interfaces would mean maintaining a second copy of a shape with one implementation and one consumer — cost without leverage.
- **A future architecture review will read this as shallowness. It is not.** `ReturnType<typeof createX>` on services and controllers is a deliberate choice, not an oversight; "the interface is inferred, so deepen it" should not be re-suggested for those layers without a concrete second implementation to point at. The interface-service ports are where that argument holds, and it has already been applied to all four.
- **Drift is a typecheck error.** Because each adapter is annotated with its port rather than merely satisfying it structurally, a method that changes shape fails at the adapter instead of surfacing at some caller later.
- **Route guards are tested once, not per route.** `guarded()` wraps a handler so a half-guarded route cannot be written, and the wrapper carries the test; behavioural per-route coverage was declined knowingly. A spike confirmed route modules import cleanly and their handlers are callable, so that coverage is available if the risk ever bites — the finding is recorded in `.scratch/architecture-deepening/issues/04-guard-coverage.md`.
